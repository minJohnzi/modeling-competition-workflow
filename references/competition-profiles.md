# Competition Profiles

本参考定义四大主流数学建模赛事的差异化硬约束与交付检查点。通用证据链流程见主文档与其余参考；当竞赛官方要求与通用规范冲突时，**竞赛官方要求为最高事实源**。

## 1. CUMCM — 全国大学生数学建模竞赛（国赛 / 高教社杯）

### 核心特征与题型倾向
- **语言与周期**：中文论文，通常 72 小时；A 题偏连续物理/几何/工程机理仿真，B 题偏离散运筹/优化调度，C 题偏统计分析/机器学习预测与商业决策。
- **版面与模板**：通常使用官方 Word 模板或 `cumcmthesis` LaTeX 模板；正文建议控制在 **20–25 页**（不含附录；实际以当年赛区要求为准），摘要控制在 **1 页内**。

### 专项必检项
1. **官方结果填报表（`result*.xlsx` / `result*.csv`）零误差对齐**：
   - 赛题提供空结果表模板时，必须编写独立脚本从 `qN/outputs/result_summary.json` 或正式输出表自动填表，禁止手工复制粘贴。
   - 逐项核对工作表名、主键 ID、行列顺序、单位（如米 vs 厘米、度 vs 弧度、万元 vs 元）、保留小数位数与空值占位符。
   - 运行独立校验脚本检查生成后的 `result*.xlsx` 是否满足官方模板范围与类型约束。
2. **支撑材料（附件压缩包）规范**：
   - 只包含可独立运行的源代码、清洗后必要中间数据或运行说明，删除 `.venv/`、`__pycache__/`、`.git/`、大体积原始数据冗余副本及调试日志。
   - 代码内只使用相对路径，并附根目录或各问 `README.md` 说明运行顺序与环境依赖。
3. **严格匿名审查（一票否决风险）**：
   - 正文、页眉页脚、附录、图片文字/水印、源代码注释、文件名及 PDF 属性元数据中，**严禁出现**参赛队号（按赛区规定仅放承诺书或指定封面）、学校名称、指导教师姓名、队员姓名及本机系统用户名路径（如 `C:\Users\<username>\...`）。

## 2. Huawei Cup / NPMCM — 中国研究生数学建模竞赛（华为杯研赛）

### 核心特征与题型倾向
- **语言与周期**：中文长论文，通常 96–108 小时；通常包含 **4–6 个高度递进的工程子问题**，涉及大规模工业数据、通信/芯片/电力/飞行器/生物医学等强背景工程机理。
- **篇幅与深度**：常见正文 **30–50 页**（含摘要与核心模型推导），强调**物理/数学机理深度**与**大规模算法工程落地能力**。

### 专项必检项
1. **“机理推导 + 算法工程”双轮驱动**：
   - 不得只套用现成黑盒库（如直接写“采用 XGBoost / NSGA-II 求解”）。必须先给出与题目工程背景结合的控制方程、数学定义或特征构造机理，再说明算法改进点。
   - 核心求解算法必须提供**标准伪代码框（Algorithm Block）**、**时间/空间复杂度分析**以及**真实规模下的运行耗时与内存记录**。
2. **多问递进的误差传递与放大控制**：
   - 若 Q1 的输出是参数辨识、信道/热阻矩阵估计或代理模型，而 Q2–Q5 在其基础上做优化或控制，必须在 `INTERFACE_CONTRACTS.md` 中传递**点估计 + 残差/置信区间**。
   - 下游章节必须至少做一次**上游参数扰动敏感性测试**，证明下游最优决策不因上游拟合误差而失效。
3. **海量/多源异构数据治理**：
   - 数据读取脚本需处理高维表格、`.mat`/`.hdf5`/`.parquet`/多工况文件夹，必须在 `data_audit` 中记录缺失、采样率对齐与量纲归一化规则。
4. **官方结果文件与匿名审查**：
   - 同国赛严格核对官方 `Result*.xlsx`/`.csv`/`.dat` 格式及全包匿名性（严禁泄漏高校与导师信息）。

## 3. MCM / ICM — 美国大学生数学建模竞赛（美赛）

### 核心特征与题型倾向
- **语言与周期**：全英文论文，通常 96 小时；MCM A/B/C 侧重连续/离散/数据，ICM D/E/F 侧重运筹网络/环境可持续/政策管理。
- **硬性页数上限**：严格遵守 COMAP 官方 **25 页硬上限**（包含 Summary Sheet、目录、正文、参考文献、附录及 AI Use Report；以当年官方规则为准）。超出页数可能直接降级或不予评阅。

### 专项必检项
1. **1 页 Summary Sheet（决定初筛上限的关键）**：
   - 必须独立成页、不超 1 页；采用高密度结构化排版（标题、研究背景 2 句、逐问模型架构与核心量化数字、敏感性/稳定性结论、模型优缺点与政策建议）。
   - 禁止在 Summary Sheet 中写泛泛定性空话，所有核心改善幅度、误差或阈值必须与正文 `result_summary.json` 严格一致。
2. **非技术交付物（Memo / Policy Letter / Executive Brief）**：
   - 美赛高频要求撰写 1–2 页给决策者（如市长、委员会、企业 CEO）的信件或备忘录。
   - 该部分**严禁堆砌公式与算法细节**，必须转化为可执行路线图、分级响应阈值、成本—收益对比表以及不超过 1–2 张极简决策图。
3. **Strengths, Weaknesses, and Future Extensions**：
   - 每条局限必须具体指向“哪个假设/数据源受限 → 影响了哪条具体结论 → 若放宽该条件如何修改方程或模型”，避免空洞套话。
4. **LaTeX 排版与 AI Use Report 合规**：
   - 推荐使用 `mcmthesis` 模板，图表导出双格式（`.png` 供审查预览，`.pdf` 供矢量嵌入，控制文件大小避免 PDF 过大）。
   - 若官方要求提交 **Report on Use of AI**，须与实际工具链使用情况保持诚实一致，并计入总页数预算。

## 4. 邀请赛与区域赛（华数杯 / 数维杯 / 亚太赛 APMCM / 认证杯）

### 核心特征与适用调整
- **周期与语言**：通常 72–96 小时；部分赛事分中文赛项与英文赛项（如 APMCM）。
- **快速标准化闭环**：
  - 直接采用标准 `qN/`（或 `QN/`）目录结构与 `templates/` 中的三张治理表。
  - 若参赛模板要求 Word（`.docx`）提交：图片使用 **300–400 dpi PNG** 插入，公式使用原生 OMML / LaTeX 转 Word 公式工具生成，防止截图模糊；若用 LaTeX 提交，优先使用同名 `.pdf` 矢量图。
  - 论文正文每问控制结构紧凑（目标—定义—约束/方程—求解—基线对比—边界），重点突出 1–3 个核心量化发现与高质量可视化图表。

---

## 5. 赛前初始化快速检查清单

在任何新比赛开始的第 1 小时（`DISCOVER` 阶段）锁定以下 6 项并写入 `PROJECT_STATE.md`：

1. **赛制 Profile**：`CUMCM` / `HUAWEI_CUP` / `MCM_ICM` / `INVITATIONAL`
2. **提交语言与排版工具**：中文 LaTeX / 中文 Word / 英文 `mcmthesis`
3. **总页数与摘要页数上限**：例如 `25 pages hard cap (MCM)` 或 `1-page abstract + 22-page body`
4. **官方结果填报表清单**：无 / `result1.xlsx, result2.xlsx`（记录文件名与校验脚本需求）
5. **匿名规则等级**：严格匿名（国赛/研赛/多数国内赛，含队号控制与路径脱敏） / 美赛控制号标注
6. **子问题划分与题型标签**：例如 `Q1: 机理仿真`, `Q2: 统计预测`, `Q3: 运筹优化`, `Q4: 评价决策`
