# Paper and Visualization

## 1. Read the governing writing rules first

正式写作前完整读取：

1. 竞赛官方模板、页数上限（如美赛 25 页硬顶）、语言要求与匿名规范（详见 [competition-profiles.md](competition-profiles.md)）；
2. 仓库内论文写作规范；
3. 当前有效的机器摘要（`result_summary.json`）与正式表格（`table_*.csv`）；
4. 已锁定的符号表、单位制和跨问题接口契约。

官方模板优先。参考论文只能提供结构或表达启发，不能成为项目数字来源。严禁编造文献、作者、期刊、年份、页码或 DOI。

## 2. Write continuously with the modeling work

避免等到全部建模结束后才凭记忆写论文。每个子问题（`qN/paper/`）支持以下两种合法草稿组织方式之一（在 `EXECUTE` 阶段同步维护）：

- **模式 A — 单文件章节草稿（推荐用于快节奏 72–96h 竞赛）**：维护 `qN/paper/section_qN.md`（或 `formal_section.md`），内部完整包含：研究目标与题意界定、数据发现、模型与公式定义、求解与伪代码、数值结果与基线对比、验证/敏感性与局限、本节结论。
- **模式 B — 五阶段模块化草稿（适合多成员精细分工）**：拆分为 `01_problem_analysis.md`、`02_data_analysis.md`、`03_model.md`、`04_validation.md`、`05_conclusion.md` 及整合稿 `formal_section.md`。

无论采用哪种模式，**代码、机器结果与论文草稿必须同一轮同步更新**。

## 3. Full-paper macro chapter outline & page budget

在 `INTEGRATE` 阶段由 Coordinator 将各问草稿合龙为全篇总论文。若竞赛官方未指定固定章节目录，按以下标准骨架与篇幅比例组装（最终以赛制硬上限为准）：

### 中文赛事标准骨架（国赛 CUMCM / 华为杯研赛 / 华数杯 / 数维杯）
- **0. 摘要与关键词**（严格 $\le 1$ 页，最后撰写；4–6 个关键词）
- **1. 问题重述**（3%–5%）：精炼梳理研究背景与各问核心要求，保留“问题一”至“问题 N”官方称谓
- **2. 问题分析与整体技术路线**（5%–8%）：揭示主要矛盾、题型归属、各问逻辑递进与整体技术路线图
- **3. 模型假设与合理性说明**：仅列真正支撑公式简化的实质性假设，逐条写明依据与影响边界
- **4. 全局统一符号说明与数据预处理/审计**（第 3+4 章合计 8%–12%）：全局符号三线表（含单位与集合）、数据清洗统计与异常核查结论
- **5. 各问模型建立、求解与结果分析**（50%–60%）：采用内容型学术标题，逐问按第 4 节 7 步主线组织，共享基础约束只在首次出现处编号
- **6. 系统检验、跨问敏感性与误差传递分析**（10%–15%）：汇总全局/跨问联合扰动、上游参数误差传递与极端压力情景分析
- **7. 模型评价、局限性、推广与结论建议**（8%–12%）：具体指明受限假设影响了哪类结论，并给出可落地建议
- **参考文献（GB/T 7714）与附录**：附录只承载长表、完整参数、补充推导与核心代码，绝不以“详见附件”替代正文论证

### 美赛标准骨架（MCM / ICM，总页数硬上限 25 页）
- **Page 1 — Summary Sheet**（严格 1 页，独立成页，高密度量化亮点）
- **Table of Contents**（0.5–1 页）
- **1. Introduction & Problem Framing**（1–2 页）：背景、任务重述与整体建模框架图
- **2. Assumptions, Notations & Data Audit**（1–1.5 页）：含理由的假设表、全局符号表与数据质量摘要
- **3–6. Model Development, Validation & Results**（11–14 页）：各子问题按第 4 节 7 步主线展开，标题使用内容型英文学术表述
- **7. Sensitivity, Stability & Error Propagation Analysis**（2–3 页）：跨参数临界相变、权重/步长稳定性与误差传递
- **8. Strengths, Weaknesses & Future Extensions**（1–1.5 页）：逐条绑定“受限假设 $\to$ 受影响结论 $\to$ 改进路径”
- **Non-Technical Deliverable: Memo / Policy Letter**（1–2 页，题目要求时）：面向指定决策者，去公式化，配 1–2 张高密度决策图与阈值收益表
- **References（IEEE/APA）、Appendices & AI Use Report**（1–2 页，严格计入 25 页总预算）

## 4. Organize each model section

进入模型章节后，按以下 7 步主线组织每问正文（章节标题采用内容型学术表述，避免只写“问题一：求解”）：

1. **研究目标与问题分析**（明确子问题类型与核心矛盾；相邻问节首显式交代沿用口径与继承/重优化/参数传递关系）；
2. **模型定义与符号说明**（引用全局统一符号表，就地补充本节局部中间变量）；
3. **核心公式、控制方程与硬约束**（阐明建立理由与量纲）；
4. **求解方法与算法设计**（通用算法只写本题选择理由、改进点、伪代码与复杂度，不抄教材历史）；
5. **数值结果与基线比较**（同时报告收益与代价）；
6. **验证、敏感性与临界边界**（呈现题型专属校验与参数相变区）；
7. **本节结论与承接输出**（明确传递给下一问的接口或精度边界，使用内容化承接而非机械位置引用）。

## 5. Make paragraphs decision-oriented

每段只表达一个中心观点（中文约 150–200 字，英文约 3–5 句）。结果分析段推荐采用：

    核心结果 -> 与基线/竞争方法比较 -> 收益与代价权衡 -> 机理原因或适用边界

结论先行，数字用于支持判断。正文不逐行复述表格，也不逐时刻口述曲线变化。

避免：

- 未做统计检验时使用“显著”；
- 无全局最优性证明时宣称“全局最优”或“理论最优”；
- 把离散有限参数网格称为“连续 Pareto 前沿”；
- “效果很好”“高精度拟合”“具有重要意义”等无数据支撑的空话；
- 用“详见附件”“参见附录代码”替代正文关键定义、公式或结论；
- 正文出现本机绝对路径、`.csv`/`.py` 文件名、代码变量名、调试日志或学校/队员/导师身份信息。

## 6. Keep terminology and numerical scope exact

- 符号首次出现时给出含义、单位、集合归属和参数/变量属性；
- 同一术语、单位、有效数字位数与时空范围全文一致；
- 指标写清样本集合、时空范围、分母和聚合方式；
- 加权指标说明权重来源；物理成本、统计误差、启发式评分和评价得分不混称；
- 修改任何口径后，同步更新摘要/Summary Sheet、正文、结论、正式表、图和官方填报表。

不同 Scope 的指标不能放在同一句或同一表行中伪装成可直接比较。

## 7. Algorithm pseudocode & table standards

- **算法伪代码框**（尤其华为杯研赛、复杂国赛 B 题与美赛高频加分项）：使用标准 `Algorithm` 格式，写清输入（Input）、输出（Output）、关键迭代步骤、收敛/停止条件，并在正文补充时间与空间复杂度分析；
- **三线表规范**：所有正式表格采用三线表，表题位于表上方，写明研究对象、时间/样本范围与单位；关键最优或推荐行加粗；多指标结果表保留与基线的绝对差与相对变化率。

## 8. Select chart types by archetype & argument task

选图必须服务具体论证任务，优先使用下表中的高信息密度主图：

| 题型 / 阶段 | 具体论证任务 | 正文推荐图型 | 避坑与附录分工 |
|---|---|---|---|
| **全局通用** | 问题机理、多问接口、求解流程 | 技术路线图 / 系统架构框图（Flowchart / Architecture） | 禁止用散乱大段文字框替代逻辑流；按第 9 节选矢量工具绘制 |
| **全局通用** | 原始数据分布、缺测与系统瓶颈 | 小提琴图 + 箱线图、经验 CDF、缺失模式矩阵 | 全量特征相关性热图放附录 |
| **Archetype I<br>连续机理与物理仿真** | 动力学演化、稳定性与极限环 | 多工况对比轨迹图、相平面图（Phase Portrait） | 同组曲线控制 $\le 4$ 条并叠加线型区分 |
| **Archetype I<br>连续机理与物理仿真** | 步长/网格收敛性与守恒验证 | 步长/网格加密收敛阶双对数图（`log-log`）、守恒残差时序图 | 若出现震荡必须同图对比更小步长结果 |
| **Archetype I<br>连续机理与物理仿真** | 二维/三维空间场（温度/浓度/流场） | 等值线填充图（Contourf）+ 矢量箭头流场（Quiver / Streamplot） | 严禁 Jet/Rainbow 彩虹色谱；改用感知均匀色谱 |
| **Archetype II<br>离散运筹与优化调度** | 主模型 vs 基线多目标权衡 | 离散非支配前沿散点图（Pareto）、分组柱状/哑铃对比图 | 多目标权衡不要画成 3D 立体柱状图 |
| **Archetype II<br>离散运筹与优化调度** | 供需平衡、资源约束与成本分解 | 堆叠面积图 / 分项正负堆叠柱状图（Waterfall / Stacked） | 明确标注容量硬上限参考虚线 |
| **Archetype II<br>离散运筹与优化调度** | 局部精确验证与典型排程展示 | MIP 下界与启发式 Gap 对比图、**局部典型窗口甘特图** | **完整全周期长甘特图必须放入附录** |
| **Archetype III<br>统计预测与故障诊断** | 预测精度与不确定性量化（UQ） | 真实值 vs 预测值曲线 + 95%/80% 置信区间阴影带（Ribbon） | 全量多站点逐序列误差图放附录 |
| **Archetype III<br>统计预测与故障诊断** | 残差健康度与模型可解释性 | 残差分布 + Q-Q 图、SHAP 蜂群图（Beeswarm）/ 排序条形图 | 严禁把相关性归因图直接标注为“因果机制” |
| **Archetype III<br>统计预测与故障诊断** | 不平衡分类与故障检测性能 | Precision-Recall（PR）曲线、概率校准曲线、归一化混淆矩阵 | 样本极度不平衡时优先放 PR 曲线而非只放 ROC |
| **Archetype IV<br>多属性评价与决策** | 权重结构与扰动排名稳定性 | 主客观权重分组对比图、权重扰动排名凹凸图（Bump Chart / Boxplot） | 排名稳定性图需标出 Spearman/Kendall 相关系数 |
| **Archetype IV<br>多属性评价与决策** | 资源分配、空间分级与政策拐点 | 分配流向桑基图（Sankey）、空间分级填色图、敏感性临界相变区图 | 全部参数二维网格扫描热图优先放附录 |

正文主图应少而强。严禁绘制 **3D 饼图 / 3D 柱图、伪 3D 透视图、彩虹配色（Jet/Rainbow）、装饰性阴影边框与低分辨率截图**。

## 9. Tooling rules: data charts vs. schematics & roadmaps

不同性质的图形必须选用匹配的工具链，防止“用数据绘图库硬拼流程图”导致的文字截断、箭头错位或分辨率不足：

1. **数据驱动统计图 / 仿真曲线 / 热图**：
   - 必须由 Python 脚本读取 `outputs/table_*.csv` 或正式数值输出生成，禁止人工截屏或 Excel 默认粗糙截图；
   - 默认复用 `templates/paper_style.py`（或项目 `shared/paper_style.py`），通过 `export_figure()` 导出 **400 dpi PNG**，并在 LaTeX 项目中同时导出同名 **`.pdf` 或 `.svg` 矢量图**。
2. **技术路线图 / 系统架构图 / 物理机理示意图**：
   - **禁止**在 `matplotlib` 中手写大量 `FancyBboxPatch` 坐标硬拼复杂多节点流程图（极易出现文字溢出与连线碰撞）；
   - **LaTeX 论文**：优先采用 **TikZ**（字体与公式和正文天然一致）或 **Graphviz (`dot`)** / **Mermaid CLI (`mmdc`)** 导出矢量 `.pdf`/`.svg`；
   - **Word 或通用论文**：优先采用声明式矢量图工具（如 **Graphviz / Mermaid / Draw.io** 或编写**结构清晰的声明式 SVG**，显式设置 `viewBox`、充足内边距与跨平台字体），渲染后同时导出 **400 dpi PNG** 供 Word 插入与视觉审查，确保无文字遮挡与交叉连线。

## 10. Apply a consistent visual system

先复用项目 `shared/` 或 `visualization/` 公共可视化接口；若项目尚未建立，直接复制 `templates/paper_style.py` 到 `shared/paper_style.py` 并调用 `apply_paper_style()` 与 `style_axis()`：

- **语义固定色板**：深墨蓝（`#26384A` 主数据）、青绿（`#237D78` 比较/改善）、朱砂红（`#C85A45` 最优/风险/临界强调）、暖金（`#D49A3A`）/灰蓝（`#5B6FA8`）辅助多类对比、浅灰（`#DCE2E5`）极简网格；
- **非颜色冗余编码**：黑白打印或色盲友好要求，多曲线必须叠加线型（`LINE_STYLES`）与标记形状（`MARKERS`）或直接数值标注；
- **统一字体与底色**：中文论文采用微软雅黑/宋体/思源黑体混排 Times New Roman（`lang="zh"`）；英文论文统一 Times New Roman 与 STIX 数学字体（`lang="en"`）；纯白或极浅暖白底（`#FCFBF8` / `#FFFFFF`）；
- **双格式导出与无内嵌大标题**：正式图至少输出 **300–400 dpi `figNN_meaning.png`**（LaTeX 同时输出同名 `.pdf`）；图片内部不放冗余大标题，完整图号、图题、样本范围与口径说明由正文图注承担。

## 11. Explain every figure and table

每张图表在正文中必须遵循闭环：

1. 先按编号（图 X / 表 X）被正文显式引用；
2. 提炼最关键的定量现象或拐点（不抄写全部坐标值）；
3. 对比基线、竞争方法或临界阈值；
4. 给出明确的建模或政策决策含义；
5. 必要时指出观测窗口或样本边界。

## 12. Write the abstract / Summary Sheet & Memo last

### 中文竞赛摘要（国赛 / 华为杯 / 华数杯等，控制 1 页内）
1. 一至两句概括研究对象、实际背景痛点与核心建模目标；
2. 逐问说明所建核心数学模型、创新机制、求解算法及核心量化结果（精确数字 + 单位 + 较基线改善）；
3. 总结整体模型的灵敏度/稳健性表现及理论/应用价值；
4. 提炼 4–6 个核心关键词。

### 美赛 Summary Sheet（严格 1 页） & Memo / Policy Letter
- **Summary Sheet**：结构化小标题 + 核心定量亮点（加粗关键数值），确保评委仅看第 1 页就能把握每问方法、关键结果、检验结论与亮点。
- **Memo / Letter**：使用目标决策者视角（非技术语言），聚焦问题严重性、分级行动方案、预期量化收益与实施风险，避免大段公式。

摘要与 Summary Sheet 不写公式推导、文件路径、代码函数名和正文未证明的结论，全部数字必须直接来自当前正式输出。

## 13. Final writing & anonymity audit

- 每条核心结论均有公式、表、图或 `result_summary.json` 支撑；
- 摘要 / Summary Sheet、正文、结论、图表和官方填报表数字完全一致；
- 符号表、单位制、Scope 和小数精度全文一致；
- 图表编号连续且正文引用零遗漏；
- 正文与图表中无本机路径、代码字段名和调试过程描述；
- 严格满足赛制匿名要求（无队号、校名、队员及指导教师信息泄漏）；
- 总页数符合赛制硬上限（如美赛 $\le 25$ 页）；
- 参考文献真实存在且引用格式全文统一；
- 附录只承载不影响主线理解的补充代码、长表和详细推导。
